# Кузница модов Alem

Веб-конструктор, в котором мод для игры **Alem** собирается без единой ручной
правки JSON: открываете вкладку («Оружие», «Одежда», «Ресурсы»…), заполняете
поля, жмёте «Добавить», а в конце — «Скачать мод (.zip)». Архив уже готов к
установке через **Меню → МОДЫ → ВЫБРАТЬ ФАЙЛ**.

Вся логика (формы, проверка JSON, сборка `.zip` через JSZip) работает
**в браузере**. Node.js/Express нужен только для одного: раздать эти файлы —
либо у вас на компьютере, либо на любом бесплатном хостинге.

```
mod-builder/
├── package.json              зависимости и команда запуска
├── server.js                 Express-сервер (раздаёт папку public/)
├── .gitignore
├── .github/workflows/
│   └── deploy-pages.yml      автодеплой public/ на GitHub Pages
└── public/
    ├── index.html            разметка, вкладки
    ├── style.css              тема
    ├── schemas.js             описание полей каждой таблицы мода
    └── app.js                 вся логика: формы, автосохранение, экспорт
```

---

## 1. Запуск на своём компьютере

Нужен установленный [Node.js](https://nodejs.org) версии 18 или новее
(проверить: `node -v`).

```bash
cd mod-builder
npm install
npm start
```

Откройте в браузере **http://localhost:3000** — конструктор готов к работе.
Остановить сервер — `Ctrl+C` в терминале.

Работу можно закрывать и продолжать позже: всё, что вы вводите, автоматически
сохраняется в `localStorage` браузера (кнопка **«Очистить всё»** в левой
колонке стирает это хранилище). Для переноса проекта на другой компьютер или
для резервной копии — кнопки **«Сохранить проект»** / **«Загрузить проект»**:
они работают с отдельным `.json`-файлом, в который попадает вообще всё,
включая загруженные текстуры.

## 2. Как пользоваться конструктором

1. Вкладка **«Мод»** — `id`, название, автор, версия, описание. `id` должен
   быть уникальным и латиницей — по нему мод узнаётся в списке.
2. Вкладки **«Оружие» / «Одежда» / «Ресурсы» / «Рецепты» / «Постройки» /
   «Технологии» / «Персонажи»** — форма добавления сверху, список уже
   добавленных записей снизу. У каждой записи есть **«детали»** (сырой JSON,
   как он попадёт в файл), **«Изменить»** и **«Удалить»**.
   - Поля, которые вы не тронули, в файл не попадают — ровно так, как того
     требует система слияния по ключу: игра сама подставит свои значения.
   - Поля вида «доп. ингредиенты (JSON)» — это массивы объектов
     `[{"res":"Rivets","count":4}]`; форма проверяет, что вы ввели
     синтаксически верный JSON, и покажет причину ошибки, если нет.
3. Вкладка **«Технологии»** — не забывайте про поле **«Открывает ключи»**:
   без него новое оружие/одежда/рецепт останутся в таблицах, но их нигде
   нельзя будет сделать.
4. Вкладка **«Перевод»** — пары «русская строка → английский перевод» для
   `loc.json`. Ключ должен совпадать с текстом в таблицах символ в символ.
5. Вкладка **«Текстуры»** — загружайте PNG, для каждого впишите путь ровно
   такой же, как у оригинальной картинки в игре (без начального `textures/`
   — конструктор добавит его сам), например `Guns/kylysh/kylysh-right.png`.
6. Вкладка **«Экспорт»**:
   - **«Проверить JSON»** — ищет повторяющиеся ключи, не заполненный `id`
     мода, текстуры без пути и другие частые ошибки, не трогая файлы.
   - **«Скачать мод (.zip)»** — собирает `mod.json`, все непустые таблицы и
     папку `textures/` внутри папки с именем мода и скачивает архив. Пустые
     таблицы в архив не попадают вообще.
   - Ниже — предпросмотр итогового содержимого каждого файла.

## 3. Публикация проекта на GitHub

### 3.1. Один раз — создать репозиторий

```bash
cd mod-builder
git init
git add .
git commit -m "Кузница модов Alem: первая версия"
```

Создайте пустой репозиторий на [github.com/new](https://github.com/new)
(без README/лицензии — они уже есть локально), затем свяжите его и отправьте
код:

```bash
git branch -M main
git remote add origin https://github.com/<ваш-логин>/<имя-репозитория>.git
git push -u origin main
```

Дальше при любых изменениях:

```bash
git add .
git commit -m "что изменилось"
git push
```

### 3.2. Способ А — GitHub Pages (бесплатно, без сервера)

Так как весь конструктор — статические файлы в `public/`, отдельный Node-сервер
для публичного доступа не нужен. В репозитории уже лежит workflow
`.github/workflows/deploy-pages.yml`, который при каждом `git push` в ветку
`main` сам публикует папку `public/`.

Включить один раз:
1. На GitHub откройте репозиторий → **Settings → Pages**.
2. В поле **Source** выберите **GitHub Actions** (не «Deploy from a branch»).
3. Сделайте любой `git push` — во вкладке **Actions** запустится workflow
   «Deploy to GitHub Pages».
4. После завершения сайт будет доступен по адресу вида
   `https://<ваш-логин>.github.io/<имя-репозитория>/`.

Это самый простой вариант: никакой Node.js на сервере не выполняется,
GitHub просто раздаёт файлы.

### 3.3. Способ Б — Node.js-хостинг (Render.com, бесплатный план)

Если хочется именно работающий `npm start` в интернете (например, чтобы
позже добавить серверную часть — сохранение проектов в базу и т.п.):

1. Зарегистрируйтесь на [render.com](https://render.com) и войдите через
   GitHub.
2. **New → Web Service** → выберите репозиторий `mod-builder`.
3. Настройки:
   - **Runtime**: `Node`
   - **Build Command**: `npm install`
   - **Start Command**: `npm start`
   - **Instance Type**: `Free`
4. Нажмите **Create Web Service**. Через пару минут Render выдаст адрес вида
   `https://mod-builder.onrender.com` — Express-сервер из `server.js`
   раздаёт тот же `public/`, что и локально.
5. При каждом `git push` в `main` Render пересобирает и обновляет сайт сам.

(Railway.app и Fly.io подключаются тем же способом: «New project from GitHub
repo», build `npm install`, start `npm start`.)

## 4. Чек-лист перед раздачей мода игрокам

- Мод включается и выключается без ошибок в карточке.
- Все новые вещи реально появляются в станках — проверено в новой игре.
- У каждой новой строки есть перевод в `loc.json`.
- Картинки на месте: в руке, за спиной, на земле, в списке заказов.
- `id` мода уникален и не совпадает с чужими.
- В архиве лежит папка мода (или её содержимое) и внутри есть `mod.json`.
- В описании написано, для какой версии игры мод и что он меняет.

## 5. Технические детали

- Фронтенд — обычный HTML/CSS/JS без сборщиков, зависимость одна:
  [JSZip](https://stuk.github.io/jszip/) через CDN (упаковка архива в
  браузере, файлы никуда не отправляются — всё остаётся на вашем
  компьютере).
- Бэкенд — Express, единственная задача которого — отдавать статику
  (`app.use(express.static('public'))`), поэтому его несложно заменить на
  любой другой сервер или вовсе на статический хостинг (см. способ А выше).
- Схема всех полей таблиц (`weapons.json`, `apparel.json`, `resources.json`,
  `recipes.json`, `buildings.json`, `techs.json`, `pawns.json`, `loc.json`)
  описана декларативно в `public/schemas.js` — если в игре появятся новые
  поля, достаточно дописать их туда, форма и таблица перестроятся сами.
