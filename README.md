# Кузница модов Alem

Веб-конструктор, в котором мод для игры **Alem** собирается без единой ручной
правки JSON: открываете вкладку («Оружие», «Одежда», «Ресурсы»…), заполняете
поля, жмёте «Добавить», а в конце — «Скачать мод (.zip)». Архив уже готов к
установке через **Меню → МОДЫ → ВЫБРАТЬ ФАЙЛ**.

Вся логика (формы, проверка JSON, сборка `.zip` через JSZip) работает
**в браузере**. Node.js/Express нужен только для одного: раздать эти файлы —
либо у вас на компьютере, либо на любом бесплатном хостинге.

```
mod-builder/
├── package.json              зависимости и команда запуска
├── server.js                 Express-сервер (раздаёт папку public/)
├── .gitignore
├── .github/workflows/
│   └── deploy-pages.yml      автодеплой public/ на GitHub Pages
└── public/
    ├── index.html            разметка, вкладки
    ├── style.css              тема
    ├── schemas.js             описание полей каждой таблицы мода
    └── app.js                 вся логика: формы, автосохранение, экспорт
```

---

## 1. Запуск на своём компьютере

Нужен установленный [Node.js](https://nodejs.org) версии 18 или новее
(проверить: `node -v`).

```bash
cd mod-builder
npm install
npm start
```

Откройте в браузере **http://localhost:3000** — конструктор готов к работе.
Остановить сервер — `Ctrl+C` в терминале.

Работу можно закрывать и продолжать позже: всё, что вы вводите, автоматически
сохраняется в `localStorage` браузера (кнопка **«Очистить всё»** в левой
колонке стирает это хранилище). Для переноса проекта на другой компьютер или
для резервной копии — кнопки **«Сохранить проект»** / **«Загрузить проект»**:
они работают с отдельным `.json`-файлом, в который попадает вообще всё,
включая загруженные текстуры.

## 2. Как пользоваться конструктором

На самом сайте теперь есть вкладка **«Инструкция»** (открывается первой) —
то же самое по шагам, только прямо в интерфейсе, без переключения на GitHub.
Здесь — то же самое чуть подробнее.

1. Вкладка **«Мод»** — `id`, название, автор, версия, описание. `id` должен
   быть уникальным и латиницей — по нему мод узнаётся в списке.
2. Вкладки **«Оружие» / «Одежда» / «Ресурсы» / «Рецепты» / «Постройки» /
   «Технологии» / «Персонажи»** — форма добавления сверху, список уже
   добавленных записей снизу. Обязательно только «Название» (и «Станок» у
   рецептов) — остальное можно оставить пустым. У каждой записи есть
   **«детали»** (сырой JSON, как он попадёт в файл), **«Изменить»** и
   **«Удалить»**.
   - Поля, которые вы не тронули, в файл не попадают — ровно так, как того
     требует система слияния по ключу: игра сама подставит свои значения.
   - Поля вида «доп. ингредиенты (JSON)» — это массивы объектов
     `[{"res":"Rivets","count":4}]`; форма проверяет, что вы ввели
     синтаксически верный JSON, и покажет причину ошибки, если нет.

### Автоматизация — что конструктор теперь делает сам

- **Обязательно писать почти нечего.** У оружия, одежды, ресурсов, рецептов
  и технологий обязательно только поле **«Название»** — `id` конструктор
  сгенерирует из него сам (транслитерацией, латиницей: «Кылыш» → `kylysh`,
  «Мифрил» → `Mithril`). Захотите свой `id` — впишите вручную, поле не
  заблокировано.
- **Технологии сами не забываются.** У форм «Оружие», «Одежда», «Рецепты» и
  «Постройки» внизу есть блок **«⚙ Открыть в технологиях»**: выберите уже
  существующий тех (ключ допишется в его `unlocks` сам) или **«+ Создать
  новую технологию»** — впишите название, ветку, эпоху и стоимость, а
  `id`/`unlocks` конструктор соберёт сам (для оружия с включённым
  «Семейство материалов» — сразу по ключу `weaponfam:id@материал` на каждый
  добавленный материал). Не хотите привязывать сейчас — оставьте «Не
  привязывать», ничего не сломается, довяжете вручную на вкладке
  «Технологии» позже.
- **Ключи доступа собираются конструктором, а не руками.** Поле «Открывает
  ключи» на вкладке «Технологии» — это не текст, где легко ошибиться в
  синтаксисе `weaponfam:kylysh@iron`, а маленький конструктор: выбираете тип
  (`building`, `recipe`, `weapon`, `weaponfam`, `apparel`, `bed`, `wallmat`,
  `power`, `siege`, `crop`, `mech`), вписываете id/имя (для оружия, одежды,
  построек и рецептов — подсказки берутся из того, что вы уже добавили в
  моде), для `weaponfam` ещё материал — и ключ добавляется готовой строкой
  в список. Убрать ключ — крестик на чипе.
- **Перевод заводится сам.** Как только вы вписали «Название» у оружия,
  одежды, ресурса, техи или биографии — на вкладке «Перевод» тут же
  появляется черновая строка (транслитерация). Её стоит поправить руками,
  но по умолчанию она уже есть — `loc.json` не окажется пустым.
- **Номер `look` для одежды подставляется сам.** Как только вы выбрали слот
  (Head/Torso/TorsoOver/ArmorOver/Legs), поле «Номер картинки слоя» само
  заполняется первым свободным номером после встроенных в игру (для
  Head/Torso/TorsoOver/ArmorOver игра занимает 0–2, поэтому свои начинаются
  с 3; для Legs — с 0), с учётом уже добавленных вами вещей в этом слоте.
  Впишете число вручную — автоподстановка не станет его перезаписывать.
- **«Размер» и прочие характеристики оружия можно не выдумывать.** В форме
  «Оружие» сверху есть выпадающий **«Шаблон»** (нож / меч / копьё / дубина /
  лук / пистолет / ружьё) — подставит черновые `dmg`, `interval`, `range`,
  `drawScale` («Размер картинки»), `dtype` и `craftWork`, от которых удобно
  оттолкнуться. Это не готовый баланс, а стартовая точка — уже заполненные
  вами поля шаблон не трогает.
- **Пустые вещи не остаются пустыми.** Если у оружия не тронуть ни шаблон,
  ни характеристики — при сохранении конструктор сам подставит безопасный
  базовый набор (ближний бой, урон 6, интервал 1.6 и т.д.), чтобы оружие не
  осталось «нулевым». То же для одежды: слот, материал, прочность и номер
  картинки подставятся сами, если их не трогали.
- **«Проверить JSON» следит за обязательным сама.** Кнопка на вкладке
  «Экспорт» сообщит, если: не задан `id`/название мода, у какой-то вещи
  повторяется ключ, вещь не открыта ни одной технологией (то есть в игре
  её нельзя будет сделать), перевод остался черновым, или у текстуры не
  указан путь. Ничего из этого руками отслеживать не нужно — просто жмите
  кнопку перед сборкой архива.
- **Материал выбирается из списка, а не вписывается руками.** Поля «Материал
  1/2» у оружия, «Материал пошива» у одежды, «Ресурс» у вариантов клинка,
  «Ингредиент 1/2» и «Результат» у рецептов, «Материал» у построек — везде
  выпадающий список: готовые ресурсы игры (дерево, железо, бронза, сталь,
  ткань, кожа и т.д.), сгруппированные по категориям, плюс ваши собственные
  ресурсы из этого мода, плюс пункт **«+ Новый ресурс…»** — впишите название
  и нажмите Enter (или просто уйдите из поля) — ресурс тут же появится и в
  списке, и на вкладке «Ресурсы», без переключения вкладок.
- **«Доп. материалы» — тоже не JSON, а чипы.** Поля вида «доп.
  ингредиенты»/«доп. компоненты» у оружия, одежды, рецептов и построек —
  выбираете материал (тем же списком) и количество, жмёте «Добавить
  материал» — готово. Убрать — крестик на чипе.
- **Один look в слоте — одна вещь.** Если у одежды уже занят, скажем, look 3
  в слоте Torso, следующая вещь в этом слоте получит 4 сама (см. выше) — но
  если вы поменяете номер руками и он совпадёт с чужим, «Проверить JSON»
  на вкладке «Экспорт» это заметит и предупредит: в игре такие вещи
  наложатся друг на друга, у каждой в одном слоте должен быть свой номер.

3. Вкладка **«Технологии»** — не забывайте про поле **«Открывает ключи»**:
   без него новое оружие/одежда/рецепт останутся в таблицах, но их нигде
   нельзя будет сделать. **Делать это вручную обычно не нужно** — см. ниже.
4. Вкладка **«Перевод»** — пары «русская строка → английский перевод» для
   `loc.json`. Ключ должен совпадать с текстом в таблицах символ в символ.
5. Вкладка **«Текстуры»** — путь собирается сам, вручную писать не нужно.
   Выберите категорию сверху:
   - **«Оружие»** — выбираете оружие из списка (или вписываете название,
     если ещё не добавили) и грузите один PNG → путь
     `Guns/<id>/<id>-right.png` соберётся сам. Рисуйте горизонтально,
     остриём вправо — вертикальный клинок игра сама повернёт.
   - **«Одежда / облик»** — выбираете вещь (или вписываете слот и номер
     `look` вручную) и грузите до 5 файлов по кнопкам «Спереди»
     (обязательно), «Со спины», «Влево», «Вправо», «Женский вариант» → путь
     `char/<папка слота>/<look>_<вид>.png` соберётся сам.
   - **«Ресурс на земле»** — выбираете ресурс и грузите PNG → путь
     `Items/<id>.png` (или из поля «Путь к картинке» ресурса, если оно
     заполнено).
   - **«Другое»** — для всего остального (обломки камня и т.п.), путь
     впишите вручную, как раньше.
   У любого уже загруженного файла путь всё равно можно поправить руками в
   списке ниже — на случай, если конструктор угадал не так.

   *(Папки слоёв Head → `char/hat` и Torso/TorsoOver/ArmorOver → `char/top`
   — из инструкции; папка для Legs (`char/legs`) — по аналогии,
   документацией не подтверждена. Если штаны рисуются не туда — поправьте
   путь вручную в списке файлов.)*
6. Вкладка **«Экспорт»**:
   - **«Проверить JSON»** — ищет повторяющиеся ключи, не заполненный `id`
     мода, текстуры без пути и другие частые ошибки, не трогая файлы.
   - **«Скачать мод (.zip)»** — собирает `mod.json`, все непустые таблицы и
     папку `textures/` внутри папки с именем мода и скачивает архив. Пустые
     таблицы в архив не попадают вообще.
   - Ниже — предпросмотр итогового содержимого каждого файла.

## 3. Публикация проекта на GitHub

### 3.1. Один раз — создать репозиторий

```bash
cd mod-builder
git init
git add .
git commit -m "Кузница модов Alem: первая версия"
```

Создайте пустой репозиторий на [github.com/new](https://github.com/new)
(без README/лицензии — они уже есть локально), затем свяжите его и отправьте
код:

```bash
git branch -M main
git remote add origin https://github.com/<ваш-логин>/<имя-репозитория>.git
git push -u origin main
```

Дальше при любых изменениях:

```bash
git add .
git commit -m "что изменилось"
git push
```

### 3.2. Способ А — GitHub Pages (бесплатно, без сервера)

Так как весь конструктор — статические файлы в `public/`, отдельный Node-сервер
для публичного доступа не нужен. В репозитории уже лежит workflow
`.github/workflows/deploy-pages.yml`, который при каждом `git push` в ветку
`main` сам публикует папку `public/`.

Включить один раз:
1. На GitHub откройте репозиторий → **Settings → Pages**.
2. В поле **Source** выберите **GitHub Actions** (не «Deploy from a branch»).
3. Сделайте любой `git push` — во вкладке **Actions** запустится workflow
   «Deploy to GitHub Pages».
4. После завершения сайт будет доступен по адресу вида
   `https://<ваш-логин>.github.io/<имя-репозитория>/`.

Это самый простой вариант: никакой Node.js на сервере не выполняется,
GitHub просто раздаёт файлы.

### 3.3. Способ Б — Node.js-хостинг (Render.com, бесплатный план)

Если хочется именно работающий `npm start` в интернете (например, чтобы
позже добавить серверную часть — сохранение проектов в базу и т.п.):

1. Зарегистрируйтесь на [render.com](https://render.com) и войдите через
   GitHub.
2. **New → Web Service** → выберите репозиторий `mod-builder`.
3. Настройки:
   - **Runtime**: `Node`
   - **Build Command**: `npm install`
   - **Start Command**: `npm start`
   - **Instance Type**: `Free`
4. Нажмите **Create Web Service**. Через пару минут Render выдаст адрес вида
   `https://mod-builder.onrender.com` — Express-сервер из `server.js`
   раздаёт тот же `public/`, что и локально.
5. При каждом `git push` в `main` Render пересобирает и обновляет сайт сам.

(Railway.app и Fly.io подключаются тем же способом: «New project from GitHub
repo», build `npm install`, start `npm start`.)

## 4. Чек-лист перед раздачей мода игрокам

- Мод включается и выключается без ошибок в карточке.
- Все новые вещи реально появляются в станках — проверено в новой игре.
- У каждой новой строки есть перевод в `loc.json`.
- Картинки на месте: в руке, за спиной, на земле, в списке заказов.
- `id` мода уникален и не совпадает с чужими.
- В архиве лежит папка мода (или её содержимое) и внутри есть `mod.json`.
- В описании написано, для какой версии игры мод и что он меняет.

## 6. Технические детали

- Фронтенд — обычный HTML/CSS/JS без сборщиков, зависимость одна:
  [JSZip](https://stuk.github.io/jszip/) через CDN (упаковка архива в
  браузере, файлы никуда не отправляются — всё остаётся на вашем
  компьютере).
- Бэкенд — Express, единственная задача которого — отдавать статику
  (`app.use(express.static('public'))`), поэтому его несложно заменить на
  любой другой сервер или вовсе на статический хостинг (см. способ А выше).
- Схема всех полей таблиц (`weapons.json`, `apparel.json`, `resources.json`,
  `recipes.json`, `buildings.json`, `techs.json`, `pawns.json`, `loc.json`)
  описана декларативно в `public/schemas.js` — если в игре появятся новые
  поля, достаточно дописать их туда, форма и таблица перестроятся сами.
